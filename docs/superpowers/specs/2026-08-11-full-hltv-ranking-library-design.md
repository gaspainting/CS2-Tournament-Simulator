# HLTV 完整排名职业库设计

## 背景

当前应用只内置 16 支职业队和 80 名选手。数据库与导出文件均直接继承这份固定种子，因此“职业名单”不是 HLTV 的完整职业排名库。现有 Tauri 更新器使用无浏览器 HTTP 请求访问 HLTV，当前会被 Cloudflare 的 JavaScript/Cookie 验证页拦截，无法补齐数据库。

本次更新使用 HLTV 2026-08-10 世界排名页作为队伍与现役五人阵容的权威快照，并使用 2026-02-11 至 2026-08-11 的 Players Stats 表补充 Rating。排名页当前包含 215 支队伍，每队五名首发，共 1,075 个阵容位置。

## 数据范围

- 收录 HLTV 2026-08-10 世界排名页中的全部 215 支队伍，不截断为 Top 30 或 Top 50。
- 每支队伍使用排名卡片列出的五名现役选手。
- 选手内部 ID 使用 `hltv-player-<HLTV ID>`，队伍内部 ID 使用 `hltv-team-<HLTV ID>`。
- 游戏 ID、真实姓名和国籍来自排名页的选手链接与图片属性。
- 真实姓名去除显示文本中的单引号游戏 ID；无法可靠拆分时保留 HLTV 原始显示名。
- Rating 按 HLTV 玩家 ID 从近六个月 Stats 表匹配；无样本时使用 `1.00`，并将 `sampleStatus` 标为 `insufficient`。
- 年龄无法从排名页或 Stats 表稳定获得，统一使用现有兼容默认值 `24`。
- 位置无法从这两个来源稳定获得，统一使用 `Unset`，不伪造 IGL、AWPer 等角色。
- 队伍地区使用 `International`，颜色按 HLTV 队伍 ID 确定性生成，稳定度使用现有职业更新默认值 `0.72`。
- 队伍评分继续使用 `round(1000 + 五名首发平均 Rating * 600)`。

## 数据文件与运行时结构

新增 `src/data/hltvProfessionalSnapshot.json` 保存可审计的结构化快照。`src/data/proTeams.ts` 不再维护超长手写数组，而是验证并映射 JSON，导出既有的 `PROFESSIONAL_PLAYERS`、`PROFESSIONAL_TEAMS` 和 `PROFESSIONAL_SNAPSHOT_DATE`，从而保持调用方接口不变。

快照包含：

- 数据日期与两个 HLTV 来源 URL；
- 215 支队伍的排名、HLTV ID、名称、五人阵容；
- 1,075 名唯一选手的 HLTV ID、游戏 ID、真实姓名、国籍和 Rating；
- 未匹配到 Stats 样本的选手数量，便于后续审计。

生成快照时必须拒绝：

- 重复队伍 ID；
- 重复选手 ID；
- 同一选手出现在两支排名队伍；
- 不是五名唯一首发的队伍；
- 队伍引用不存在的选手；
- 空白名称、无效 Rating 或非法 HLTV ID。

职业选手的官方游戏 ID 不做虚构式改名。若 HLTV 官方存在同名选手，内部 ID 仍保持唯一，导出中保留官方游戏 ID。

## 现有数据库迁移

在 `AppDatabase.migration` 中新增 `professionalSnapshotVersion`，完整排名快照版本为 `2`。

新数据库直接写入版本 2，并使用 215 队职业库。旧数据库加载时：

1. 若迁移版本已经达到 2，不重复处理。
2. 若职业快照仍精确匹配旧内置基线（来源日期 `2026-08-10`、16 队、80 人），用完整排名职业队与选手替换当前职业库。
3. 若用户已经通过导入、在线更新或手工维护得到不同职业库，不覆盖其职业数据，只记录迁移版本。
4. 虚构队、自建队、模板、设置和存档不变。
5. 已完成或进行中的赛事继续使用 `teamSnapshots`，不得因职业库替换而改变历史阵容或比赛结果。

迁移后启动应用并保存数据库，使当前本机 SQLite 与新职业库一致。
