# 虚构选手游戏 ID 全局唯一设计

## 背景

内置虚构名单包含 50 支战队和 250 名选手。当前中文游戏 ID 由固定姓名池循环取模生成，导致 25 个游戏 ID 在不同战队之间各出现两次。离线生成虚构战队也使用有限组合公式，生成数量增加后同样可能重复。

本次修改只处理游戏 ID 唯一性。真实姓名、年龄、位置、Rating、队伍名称、内部玩家 ID 和历史赛事快照保持不变。

## 目标

- 内置 250 名虚构选手的游戏 ID 全局唯一。
- 每次离线生成得到的虚构选手游戏 ID 在生成结果内唯一，并且合并到现有数据库时不与已有选手冲突。
- 中文选手继续使用纯中文游戏 ID；英文选手继续使用纯英文或英文加数字游戏 ID。
- 当前用户数据库中的旧重复游戏 ID 在升级后自动修正一次。
- 用户手动修改过的游戏 ID 不被迁移覆盖。
- 已保存赛事中的阵容快照不修改。

## 方案

### 确定性冲突消解

生成器先按现有公式产生首选游戏 ID，并在本次生成过程中维护已使用名称集合。首选名称未被占用时原样保留；发生冲突时，从对应语言的候选空间中按稳定顺序选择第一个未使用名称。

中文候选由中文姓氏和中文名组合，保证不引入字母或数字。英文候选由英文代号和数字组合。相同输入、种子和队伍顺序必须得到相同结果，保证测试、存档和导出可复现。

内置数据保留首次出现的旧游戏 ID，只替换后续 25 个冲突项，因此其余 225 名选手名称不变。

### 现有数据库迁移

程序导出内置玩家的旧名称到新名称映射，并在数据库迁移元数据中记录虚构游戏 ID 迁移版本。

加载旧数据库时，只在以下条件全部满足时更新玩家的 `nickname`：

- 玩家内部 ID 属于内置虚构名单；
- 当前游戏 ID 仍等于该玩家的旧内置游戏 ID；
- 数据库尚未应用本次迁移。

如果用户已手动修改该玩家名称，当前值与旧内置值不同，迁移必须保留用户值。迁移只修改队伍库玩家对象，不修改赛事保存的 `teamSnapshots`。

### 离线生成与数据库合并

离线生成器在一个生成批次中保证游戏 ID 唯一。合并生成结果时，继续使用现有碰撞重映射流程处理内部 ID，并在必要时对游戏 ID 做确定性二次消解，避免与数据库中职业、自建或既有虚构选手的名称冲突。

## 非目标

- 本次不处理真实姓名重复。
- 本次不修改职业队或职业选手数据。
- 本次不重命名已经唯一的虚构游戏 ID。
- 本次不回写历史赛事快照中的显示名称。
