# CS2 通用赛事模拟器设计

## 目标

将现有固定 32 队 Major 模拟器升级为独立的通用 CS2 赛事桌面应用。应用支持职业、自建和虚构队伍，允许用户创建并永久保存多支自建队，配置常见或完全自定义的赛事，并在操纵队比赛中手动填写结果。

## 产品范围

- 保留现有 Major 规则作为内置模板，不再把 Major 规则写死在赛事引擎中。
- 内置 Major、瑞士轮、单败淘汰、双败淘汰、循环联赛和分组赛模板。
- 模板可复制和编辑，支持配置队伍数、阶段、晋级数、BO、败者组、季军赛和总决赛规则。
- 每个赛事选择一支操纵队；其余参赛队可手动选择，或按职业与虚构比例自动补齐。
- 同一赛事默认禁止重复队伍。
- 保留多存档，并让每个赛事存档拥有独立随机种子和队伍快照。

## 应用架构

应用保持为独立 Tauri 桌面程序，内部拆分为五个模块：

1. 队伍与选手库：管理职业、自建和虚构队伍、选手与阵容。
2. 赛事模板库：保存内置模板及用户复制或创建的自定义模板。
3. 通用赛事引擎：根据阶段配置生成对阵、积分、晋级和淘汰结果。
4. 存档系统：保存赛事配置、参赛快照、进度、历史比赛和随机种子。
5. 数据更新器：在 Tauri 后端执行 HLTV 更新、缓存、校验、回滚和在线 AI 请求。

大量结构化数据从 WebView `localStorage` 迁移到应用数据目录中的 SQLite 数据库。前端通过 Tauri 命令访问数据，赛事推进算法保持为可独立测试的 TypeScript 纯函数。

## 数据模型

### 选手

- 内部唯一 ID
- 游戏 ID
- 真实姓名
- 国籍
- 年龄
- 位置：IGL、AWPer、Rifler、Entry、Support、未设置
- 个人评分
- 来源：职业、自建、虚构
- HLTV ID（职业选手可用）
- 数据更新时间与样本状态

### 队伍

- 内部唯一 ID
- 名称与简称
- 地区与显示颜色
- 来源：职业、自建、虚构
- 五名首发
- 可选替补
- 可选教练
- 综合实力与稳定度
- HLTV ID（职业队可用）
- 数据更新时间

自建队永久进入队伍库，可重复用于不同赛事。职业和虚构队可复制为可编辑的新队伍，原始内置数据可恢复。比赛要求恰好选择五名首发；替补和教练不直接计入队伍战力。

### 赛事模板

模板包含名称、允许的队伍数和有序阶段列表。每个阶段记录类型、参赛来源、晋级规则、配对规则、BO 配置和排名规则。自定义模板必须通过结构校验后才能用于创建赛事。

### 赛事存档

存档包含赛事名称、模板快照、参赛队伍与选手快照、操纵队 ID、随机种子、当前阶段、当前轮次、对阵、积分、历史比赛和冠军。赛事开始后修改队伍库不会改变存档中的参赛快照。

## 界面设计

主界面采用适合桌面管理工具的左侧导航，不使用营销式首页。字体、图标和交互控件保持现有放大后的可读尺寸。

- 赛事存档：继续、复制、重开、导入、导出和删除赛事。
- 创建赛事：通过五步向导创建新赛事。
- 队伍库：浏览、搜索、筛选、创建和编辑队伍与阵容。
- 选手库：按名称、国籍、位置、队伍、来源和评分筛选。
- 模板库：使用、复制、编辑和删除自定义模板。
- 数据中心：查看职业库版本、执行 HLTV 更新、管理虚构名单。
- 设置：语言、在线 AI、API Key 和默认模拟选项。

创建赛事向导：

1. 填写赛事名称并选择预设模板。
2. 修改队伍数、阶段、BO、晋级和决赛规则。
3. 从队伍库选择操纵队，或现场创建并保存自建队。
4. 手动选择参赛队，或按职业与虚构比例自动补齐。
5. 检查阵容和规则，确认后创建不可变赛事快照。

缺少五名首发、同一选手重复加入、队伍数量不匹配或阶段规则冲突时，禁止开始赛事并显示具体问题。

## 通用赛事引擎

### 瑞士轮

支持配置晋级胜场、淘汰负场、避免重复交手，以及普通场、晋级场和淘汰场的 BO。首轮按实力种子配对，后续优先在相同战绩组中配对。

### 单败淘汰

支持 2 的幂次队伍数、不同轮次 BO、总决赛 BO 和可选季军赛。

### 双败淘汰

包含胜者组、败者组和总决赛，可配置总决赛是否需要败者组冠军连胜两场完成重置。

### 循环联赛

支持单循环和双循环，依次按胜场、净胜分和交手结果排序。

### 分组赛

将参赛队平均拆分为多个小组，每组采用循环或瑞士轮，并按配置名次晋级下一阶段。

### Major 模板

保留现有三阶段瑞士轮加八强单败淘汰结构，并维持各阶段 BO 规则。

### 比赛模拟

AI 对局胜率由五名首发平均评分、队伍稳定度和有限随机波动计算。职业身份不提供隐藏加成。随机数由存档种子驱动，以便复现。

操纵队比赛暂停等待用户填写系列赛比分。BO1 允许合法单场比分；BO3 允许 2:0、2:1 及反向结果；BO5 允许 3:0 至 3:2 及反向结果。提交后自动更新积分、晋级关系和后续对阵。

## 职业数据库与 HLTV 更新

应用内置一份离线职业数据库快照，并提供手动联网更新。

- 活跃选手档案提供 HLTV ID、游戏 ID、真实姓名和国籍。
- 个人资料提供年龄和当前队伍。
- Stats 提供近期评分和样本量。
- 评分优先使用近三个月数据；样本不足时回退到近十二个月；仍不足时使用中性默认值并标记数据不足。
- HLTV 未稳定提供的位置字段保存为未设置，允许用户补充。
- 更新器分页读取数据，限制请求速度，支持取消和缓存。
- 更新完成前只写临时数据；校验通过后一次性替换正式职业库。
- 更新失败或页面结构变化时保留上一份可用数据库。
- 更新前显示新增、转会、离队和评分变化摘要。

职业库记录 HLTV 数据来源日期。完整活跃名单规模随 HLTV 变化，不使用固定队伍数或选手数。

## 虚构队伍与在线 AI

应用内置约 50 支虚构队伍和 250 名选手：约 25 支纯中文队伍和 25 支纯英文队伍，每队默认五名首发。单支队伍及其选手名称保持同一种语言，不生成中英文混合名称。

虚构选手拥有合理分布的国籍、年龄、位置和评分。不同队伍的实力存在梯度。

离线生成始终可用。在线 AI 默认关闭，用户配置 OpenAI API Key 后可按地区、语言、命名风格、实力区间和数量生成名单。AI 必须返回结构化 JSON，应用校验重名、语言、年龄、位置和阵容数量后才写入数据库。API Key 保存到 Windows 凭据存储，不进入普通配置、日志、存档或导出文件。

## 存档迁移与备份

- 首次启动新版时自动读取现有 `cs2-major-simulator.saves.v2` 数据。
- 迁移前备份原始 JSON。
- 旧赛事保持原来的 32 队 Major 赛程和已经产生的结果。
- 旧队伍优先关联新版职业阵容；无法关联时创建仅属于该存档的占位阵容。
- 迁移失败时不删除原始存档，并允许继续使用旧数据。
- 支持导入和导出单个赛事、模板、自建队以及完整数据库备份。

## 错误处理

HLTV 更新、在线 AI 生成和数据库迁移均采用临时数据区，只有完整校验成功后才更新正式数据。网络失败、页面结构变化、AI 非法响应、阵容重名和赛事规则冲突均显示具体错误。删除队伍或选手不影响历史赛事快照。

## 测试策略

- TypeScript 单元测试覆盖瑞士轮、单败、双败、循环、分组晋级、随机种子和手动比分。
- 数据测试覆盖阵容校验、中文与英文命名规则、模板结构和自动补齐。
- 迁移测试覆盖旧 `v2` 存档、数据库升级和失败回滚。
- Rust 测试使用保存的 HLTV 页面样本验证解析器，不依赖实时网络。
- 在线 AI 使用固定结构响应测试，不消耗真实 API。
- 发布前运行 TypeScript 测试、Rust 测试、前端构建和 Tauri release 构建。
- 不进行耗时的桌面自动点击测试。

## 完成标准

用户可以在独立桌面程序中管理职业、自建和虚构队伍，创建常见或自定义赛事，选择任意合法队伍作为操纵队，手动提交操纵队比分，保存多个独立赛事，并在离线情况下使用完整核心功能。职业库可手动更新，在线 AI 为可选增强功能，任何联网失败均不影响已有数据和存档。
